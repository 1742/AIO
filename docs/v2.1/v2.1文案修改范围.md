# v2.1 文案修改范围

更新日期：2026-10-17。用于给文案 AI 提供当前文件索引、修改边界和交付要求。

## 本轮任务

先完善当前 v2.1 的中文文案，再按中文定稿同步英文。本轮只修改本地化文本，不改玩法脚本、数值、解锁条件或 UI 布局。

文案已按内容归档到分类文件，不再使用版本号命名的混合文件。原集中文件的中英文各181个条目均已迁移，键名、版本标记和字符串内容保持不变。

后续直接在对应分类文件中编辑，并同步维护中英文；不要重新建立按版本号集中存放文案的文件。

## 阅读顺序与版本边界

1. 阅读本清单，确定要改的文件与键。
2. 阅读当前本地化和对应运行脚本，确认触发场景、目标、结果与显示位置。
3. `docs/文案重写.md` 只作为作者设定与文风参考。它以 v4 为背景，文件索引和流程说明已有过时内容，不能直接作为本轮修改清单。
4. `docs/v2.1/v2.1设计方案.md`、`v2.1实施记录.md` 用于理解版本方向；参数和具体行为最终以当前脚本及作者最新确认内容为准。

当前路线围绕定向应用无限、专属巨构、套娃脑和亚弗戈蒙终局展开。不要恢复 v4 的无名之雾殖民地、mist 专属区划、规则科技或远程投射，也不要按照旧索引新建这些已不存在的文案文件。特殊起源直接完成飞升，不必强套普通路线的终局经历。

## 四、文风与信息边界

- 事件正文、奖励风味描述、巨构背景可以重写，用场景、意象与叙述立场表达技术和野心，避免全篇像操作手册。亚弗戈蒙是宇宙纠正机制的具象化，不随意改成有常规外交诉求的帝国。
- 按钮、条件、费用、范围、时间、退款、目标失效、项目有效期和操作提示必须清楚准确，不能为了氛围删去必要信息。
- DAIT 菜单已经显示当前费用、选中状态和范围；`AIO_DAIT_button_*_tooltip` 不重复堆叠这些内容，跳数按钮不恢复悬浮提示。终局的 `AIO_final_induction_action_tooltip`、`AIO_final_constraint_action_tooltip` 仍有有效引用，不要按名称相似一并排除。
- 局势已有目标和完成时间显示，正文不重复加入这两项。修改描述时保留真正需要解释的操作结果、取消条件与处理规则。
- `AIO_empire` 的免费和免冷却不代表免前摇。思潮针对国家，不把它改写成按跳数影响星系；打击的全境档与普通跳数范围也不能混为一谈。
- 专有名词先沿用现有名称。若提议统一“抹除／擦除”等叫法，需列明所有受影响的显示文本；本地化键仍保留原名。

## 五、必须保留的技术内容

只修改引号内的自然语言，保留键名、语言头与版本标记。以下内容不能被翻译、改写或猜测替换：

| 内容 | 例子 |
|---|---|
| 本地化引用与参数 | `$AIO_mega_04$`、`$NAME$`、`$VAL|0$`、`$AIO_DAIT_ascended_no_cooldown$` |
| 动态作用域与属性 | `[From.GetAIO_DAIT_logic_k]`、`[This.GetStarName]`、`[Owner.GetAIO_DAIT_erase_range_name]`、`[event_target:AIO_DAIT_maker.GetName]` |
| 图标标记 | `£advanced_logic£`、`£AIO_advanced_logic£`、`£sr_dark_matter£` |
| 格式符 | `§Y`、`§M`、`§!` 等颜色／样式符及其闭合；转义换行 `\n` |

不要把占位表达式展开成固定名称或固定数值，不要把字符串中的 `\n` 改成真实的跨行字符串。保留 UTF-8 BOM，并避免新增同语言重复键。

现有纯引用条目用于复用名称、颜色或原版文案，不要求全部改成独立正文；如果确需替换引用，应先检查被引用内容及显示位置。

## 六、交付与检查

建议按以下顺序交付：先DAIT操作文案，再天灾／巨构／终局叙事，再帮助文本，最后经济和配套名称。每批附修改文件及键名清单，把未决设定问题单列，不混入成品字符串。

中文定稿后再同步英文；需要翻译语气与意思，不擅自调整机制信息。新增条目的中英文应归入相同分类文件，并保留对应顺序与分组。仅调整中文的阶段请明确注明“英文待同步”，避免误认为双语已完成。

有本地代码环境时，在模组根目录运行：

```powershell
python tools/validate_v21.py
git diff --check
```

另外比较修改前后的键集合、占位符和动态表达式，确认没有漏键、变量损坏或 BOM 丢失。对照实际界面检查按钮长度、提示重复和文本裁切；静态检查不能代替游戏内显示检查。

没有代码环境时，交付按分类文件与原键分组的替换文本，不编造缺失脚本的内容，不提交对参数或键名的猜测性修改。后续按内容分类维护本地化，不建立版本号混合文件，也不通过修改运行脚本来迁就文案。
