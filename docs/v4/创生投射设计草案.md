# 创生投射设计草案

## 4. 创生：效果规格（后续版本）

> 未实施的历史构想，2026-10-13 从远程投射文档分离保留；不是当前亚弗戈蒙投射的规格，实施前需重新确认。

### 4.1 已确定的目标

创生投射作用于一片范围，由局势分阶段生效。按方案决定文明的用途：

| 方案 | 最终结果 | 需要实现的收益 |
|---|---|---|
| 军事仆从 | 成为施法者的仆从国 | 稳定提供军事支援 |
| 经济仆从 | 成为施法者的仆从国 | 稳定提供经济支援 |
| 放手发展 | 新生文明独立发展 | 不强制成为仆从；是否保留初始友好关系待定 |

目标范围已有国家时，逐渐把该国家引导为期望思潮、政府或仆从国。**本文不把「割走覆盖区建立新国家」作为默认结果**；那是另一条尚未确认的设计。

### 4.2 必须在实现前明确的边界

- 创生范围如何选取：固定跳数、空间距离或其他可视化。用户没有确定创生也制造破坏性的枢纽风暴，不自动复用亚弗戈蒙风暴效果。
- 是否也有可摧毁锚点、如何被打断、失败后哪些阶段变化保留。
- 范围跨多个国家时，是逐一改造、只改中心国家，还是禁止选择。建议首版只绑定一个明确目标国家，其他情况禁用或显式提示；不能按遍历顺序随机决定。
- 范围只有他国未殖民星系时，是否算「已有国家」；建议在预检时区分国家领土与实际殖民地。
- 覆盖部分疆域即可最终改组整个国家，还是要求首都/一定覆盖比例；这属于玩法规则，接口不会替我们决定。
- 机械、蜂巢、失落、觉醒、天灾、玩家国家是否允许改造。首版建议明确支持集合，禁止未实现分支，不能把普通思潮转换直接套给所有类型。
- 思潮、政体由玩家选定还是方案固定；方案能否中途切换、何时锁定。

### 4.3 建议阶段：无现存目标国家

下表是建议骨架，阶段名称、比例与收益数值待定。

| 阶段 | 建议效果 | 执行约束 |
|---|---|---|
| 启动：确定蓝图 | 固定范围、母星、物种方向及方案 | 先验证存在可用母星或可改造候选 |
| 第一阶段：环境塑造 | 改造选定天体，为生命提供环境 | 只改允许的目标，尊重现有保护 API |
| 第二阶段：文明孕育 | 展示文明形成、施加一次性准备效果 | 建议暂不生成无国籍人口，避免中间态归属问题 |
| 完成：建国 | 物种、人口、国家、首都、基地、领袖、科技和资源一次性初始化 | 完成标记保护，不能多建一个国家 |
| 后续 | 根据方案附庸并启用支援，或释放为普通独立国家 | 收益系统独立于已完成局势运行 |

「阶段二暂不生成人口」是稳定性建议，不是引擎限制。若希望真正提前生成生命，需要为该阶段明确人口/殖民地归属与失败处理。

完成时要构造能正常存在和发展的国家，不仅调用 `create_country`：确认首都、物种权利、政府合法性、基础科技、领袖与议会、殖民地基础建筑/区划、恒星基地、通讯及初始资源。具体初始化借鉴原版建国链，不默认新国家会自动补齐一切。

### 4.4 建议阶段：已有目标国家

| 阶段 | 建议效果 | 作用域 |
|---|---|---|
| 启动 | 记录目标国家、覆盖星系、目标思潮及方案 | 投射实例 |
| 第一阶段 | 改变范围内部分人口的思潮 | pop_group |
| 第二阶段 | 扩大人口转换，显示社会重构，锁定最终方案 | 局势 + 覆盖区人口 |
| 完成 | 明确设置国家思潮，改组政府，按方案建立仆从关系或保留独立 | country |
| 后续 | 开启军事/经济支援或放手发展 | 目标国家与施法者的关系 |

技术上，人口转换可只影响覆盖区域；`shift_ethic`、`change_government`、`set_subject_of` 都作用于整个国家。文案必须区分这两类效果。

建议保留原国家身份完成改组，而不是删除原国家再建立副本。已有战争、联邦、宗主与附庸关系、物种权利和外交条约不会因为调用一次政府修改而自动整理成期望状态；结算前需检查并明确处理。

目标国家中途灭亡或范围归属变化时，不建议静默改造新占领者。建议取消，或显式进入另一条已设计的分支。无国家路线在完成前被他国殖民，也应重新预检。

### 4.5 主要接口与作用域

| 接口 | 作用域/用途 | 注意事项 |
|---|---|---|
| `create_species` | 创建物种，保存物种目标 | 不复用易被覆盖的 last_created 太久 |
| `create_pop_group` | 在目标行星创建人口组 | 4.x 人口数量单位按现有版本校验 |
| `create_country` | 创建国家，内部 `effect` 进入新国家 | 明确 type、species、ethos、authority、civics |
| `set_owner` | 行星、舰队等对象转移归属 | 转移殖民地和星系基地需配套处理 |
| `set_capital` | 建立首都 | 参考原版初始化上下文 |
| `pop_change_ethic` | pop_group；按 amount 或 percentage 转换 | 不使用旧版单个人口循环假设 |
| `shift_ethic` | country；朝某思潮移动 | 自动协调思潮点数，不保证一次得到完整指定组合 |
| `clear_ethos`、`country_add_ethic` | country；重设组合 | 必须保证点数、政体和物种关系合法 |
| `change_government` | country；指定 authority / civics | 思潮、不可移除理念、特殊政体另行处理 |
| `set_subject_of` | country；指定宗主与 preset | 已有宗主、战争及附庸协议需测试 |
| `set_country_type` | country；切换国家类型 | 不等价于完成 AI、外交、经济初始化 |
| `add_resource`、`add_modifier` | 发放资源、挂载修正 | 明确收益来源、上限、终止条件 |
| `create_fleet` / `create_ship` / `set_owner` | 生成并交付援军 | 确认归属、维护费、失去仆从后的处理 |

局部示例，目标均假定已初始化：

```paradox
# 当前作用域：人口组。数量仅用于演示参数；正式阶段可改用 percentage。
pop_change_ethic = {
    ethic = ethic_spiritualist
    amount = 100
}

# 当前作用域：目标国家。这里只演示接口，不代表最终选定思潮。
shift_ethic = ethic_spiritualist
change_government = {
    authority = auth_imperial
    civics = random
    cooldown = no
    remove_invalid_civics = yes
}

# 当前作用域：拟成为仆从的国家；正式实现换成选定协议预设。
set_subject_of = {
    who = event_target:AIO_projection_maker
    preset = preset_vassal
}
```

`percentage` 的数值尺度应实测再定，不能仅凭参数名推断 0.25 与 25 哪个代表 25%；上例先使用 amount 展示调用形状。`preset_vassal` 已在本机 [00_agreement_presets.txt](F:/ProgramFiles/Steam/steamapps/common/Stellaris/common/agreement_presets/00_agreement_presets.txt:38) 找到；正式军事/经济方案是否采用它或自定义协议仍待定。

原版参考：

- [00_scripted_effects.txt](F:/ProgramFiles/Steam/steamapps/common/Stellaris/common/scripted_effects/00_scripted_effects.txt:74)：`create_subterranean_nation` 展示物种 → 国家 → 国家内部 effect → 通讯与目标保存；这是特殊国家示例，不是完整普通帝国初始化模板。

### 4.6 复用现有创生代码时的限制

现有 [AIO_DAIT_effects.txt](</C:/Users/13632/Documents/Paradox Interactive/Stellaris/mod/AllinOne/common/scripted_effects/AIO_DAIT_effects.txt>) 有三块相关功能：

1. `AIO_DAIT_spawn_effect`：空洞/收割星系重构，或改变未殖民天体。其空洞分支会清除天体与巨构，不能无预检地对整片已开发区域调用。
2. `AIO_DAIT_seed_effect`：随机找无人口宜居天体，生成物种、4000 人口量、国家、领袖、基地和资源。可以拆出建国辅助效果，但不要直接每个星系调用，否则会生成多个国家。现有代码还可能销毁目标星系既有基地，应排除误操作他国基地。
3. `AIO_DAIT_ethic_effect`：把国家思潮朝相反方向改变，并随机改政府。这不符合「指定期望蓝图」，不能作为新创生的最终政府效果直接复用。

建议新建明确的 `AIO_projection_genesis_*` effects，以指定母星、指定新国家和指定蓝图为输入；底层安全换天体 API 可以复用。

### 4.7 军事与经济仆从的实现路线

自定义 country type 可控制 `ai.enabled`、`construction`、`internal_policies`、`tech`，并配置军事、外交、经济等模块。参考 [00_country_types.txt](F:/ProgramFiles/Steam/steamapps/common/Stellaris/common/country_types/00_country_types.txt) 顶部注释与 `default`，不要仅复制 `ai = { enabled = no }` 就认为帝国仍会正常行动。

建议先把支援收益与 AI 经营解耦，再决定是否需要特殊类型：

| 支援方式 | 可实施路线 | 待定问题 |
|---|---|---|
| 军事 | 周期生成舰队，直接交给宗主；或保留仆从所有并由军事 AI 操纵 | 一次规模、周期、维护费、直接控制还是 AI 支援 |
| 经济 | 周期脚本向宗主结算；或采用国家产出修正/附庸贡赋 | 固定收入还是按文明规模增长，是否模拟真实扣款 |
| 自由文明 | 普通国家类型和常规 AI，不启动强制支援系统 | 初始科技、关系、思潮后续能否自然变化 |

候选路线：原版专业附庸 [specialist_subject_types](F:/ProgramFiles/Steam/steamapps/common/Stellaris/common/specialist_subject_types/00_specialist_subject_types.txt) 中的 `specialist_bulwark`（军事）、`specialist_prospectorium`（资源）、`specialist_scholarium`（科研）已自带支援机制，可减少自定义国家类型和周期结算事件；原版宇宙创生天灾目标 `crisobj_have_scholarium_vassals` 与之相关。是否采用待定。

「仆从定期替宗主生成资源」与「从仆从实际库存扣款转移」是不同玩法，需明确选择。收益事件应验证宗主仍存在且关系仍成立；失去附庸关系后停止，不因保存的旧 event target 继续发奖励。

若创建特殊类型，需保留所需的标准外交/经济/领袖/科技模块，并测试协议界面、参战、市场、发展和原版只匹配 `is_country_type = default` 的流程。切类型不会自动赋予高质量 AI。
